# Графика: OpenGL и выбор видеоадаптера

## Что изменилось

Игра по-прежнему собирает кадр из `pygame.Surface`: спрайты, свет, HUD и
игровая логика остались на CPU. На видеоадаптер вынесена **финальная
стадия кадра**:

1. игра рисует кадр в offscreen Surface;
2. Surface загружается в GPU-текстуру;
3. OpenGL растягивает её на окно и при включённых эффектах добавляет
   мягкое свечение ярких участков;
4. буфер выводится на экран.

Это даёт GPU-масштабирование, фильтрацию и эффекты без переписывания
всех игровых объектов на шейдеры. Если OpenGL или PyOpenGL недоступны,
игра автоматически переходит в режим `CPU · SDL`.

## Установка

```bash
python -m pip install -r requirements.txt
```

`PyOpenGL` необязателен: без него игра запустится в CPU-режиме.

## Настройки

В паузе откройте **Настройки**. Доступны четыре пункта:

- **Громкость** — `A/D` или `←/→`.
- **Рендер** — `OpenGL · GPU` или `CPU · SDL`. Переключение происходит
  без сброса текущего забега.
- **Видеоадаптер** — `A/D` переключает вариант, `Enter` применяет выбор
  и перезапускает игру.
- **GPU-эффекты** — мягкое свечение; влияет только на OpenGL-режим.

В строке рендера показан **фактический** адаптер из `GL_RENDERER`, а не
только сохранённый выбор. Это позволяет сразу увидеть, действительно ли
Windows переключила контекст на дискретный GPU.

## Как выбирается адаптер

Windows не даёт приложению переключить уже созданный OpenGL-контекст.
Игра записывает предпочтение приложения в

```text
HKCU\Software\Microsoft\DirectX\UserGpuPreferences
```

для текущего `python.exe` (или собранного `.exe`):

- `GpuPreference=2` — высокая производительность / дискретный GPU;
- `GpuPreference=1` — энергосбережение / встроенный GPU;
- `GpuPreference=0` — автоматически.

Затем игра перезапускается, и новый процесс создаёт OpenGL-контекст уже
с учётом предпочтения. При запуске из исходников Windows видит именно
`python.exe`, поэтому предпочтение действует на все Python-приложения,
запущенные этим интерпретатором. При сборке в `.exe` оно будет
относиться только к игре.

Список адаптеров читается через `Win32_VideoController`; виртуальные
дисплеи (iDisplay и подобные) отфильтровываются. Перечисление выполняется
в фоновом потоке, чтобы не подвешивать первый кадр. Windows различает
только класс «высокая производительность / энергосбережение», поэтому
при двух дискретных GPU конкретную карту всё равно выбирает система.

## Файл настроек

Выбор рендера и адаптера сохраняется в `video_settings.json` рядом с
`graphics_backend.py`. Это настройки видео, а не сохранение прогресса.
Файл можно удалить — игра вернётся к значениям по умолчанию
(`OpenGL`, авто-адаптер, эффекты включены).

## Производительность

Замеры на этой машине (Intel UHD, 1024×768):

- CPU/SDL: около 6.1 мс на `draw()` + около 0.35 мс на `flip()`;
- OpenGL: около 6.2 мс на `draw()` + около 1.6 мс на загрузку текстуры,
  шейдер и своп.

То есть финальная GPU-презентация добавляет около 1–2 мс; основная
стоимость кадра по-прежнему приходится на CPU-отрисовку сцены. Для
максимального FPS на встроенной графике можно выбрать `CPU · SDL`;
OpenGL-режим даёт GPU-эффекты, фильтрацию и возможность выбрать
дискретный адаптер. Полный перенос игровой геометрии на GPU потребовал
бы отдельного sprite-batcher и переписывания всех вызовов отрисовки.
